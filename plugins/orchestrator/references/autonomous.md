# Autonomous mode (`/orchestrator:auto`)

Unattended runs (typically overnight). The interactive session only does the start contract and, later, the review. In between an **external supervisor** (`scripts/auto-supervisor.mjs`) drives headless Claude ticks and adapter calls and writes files, never terminal output. Invariant #1: a run never aborts because of usage limits, login hiccups, network failure or a crashed process; it waits, reroutes or retries, and an unrecoverable external failure turns into `waiting` (zero-token probes + a notification).

## Architecture
- **Guardian** (`auto-supervisor.mjs --run DIR`, detached, no inherited stdio) holds the keep-awake helper, restarts the **engine** child (`--engine`) with backoff when it dies, and kills and restarts it when its heartbeat goes stale (watchdog). Single instance per run: `guardian.lock` / `supervisor.lock` (`wx` creation, stale takeover by pid + heartbeat).
- **Engine** (`lib/auto-engine.mjs`): plan -> for each task in dependency order: route, tick, guard the diff, run checks, review, checkpoint commit + tag -> final (full tests, whole-diff cross-family review, security lens when risk is high) -> report. All state transitions are atomic (`state.json` + `.bak`, `seq`); on start it recovers from the files (state, else rebuild from `contract.yaml` + `plan.json` + checkpoint tags). Context stays bounded: each tick gets a self-contained prompt from the contract and the task, never the history.
- **Ticks**, not one long session: every unit of work is a `claude -p` call (`--output-format stream-json --verbose`, `--permission-mode dontAsk --permission-prompts none --setting-sources local --settings <generated> --tools <list>`, `--session-id` first, `--resume` after a limit/crash so a task continues in its own session). No bypass mode, ever. `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` are removed from the child env (the subscription login is the only credential), `DISABLE_AUTOUPDATER=1`. GPT/Grok/Gemini work through the existing adapters (`run-*.mjs`), their sandbox and privacy gate unchanged.
- **Isolation**: worktree `~/.claude/orchestrator/auto/<id>/worktree` on branch `auto/<id>` cut from the base SHA. The only operations in the user's checkout are `git worktree add -b` (start) and, on the explicit yes, `merge`. `lib/auto-core.mjs` `createGit` refuses push, fetch, pull, clone, remote, config and any mutation of the user's checkout. Checkpoint = commit + tag after verified checks; red checks roll back to the previous checkpoint (uncommitted work is first saved under `refs/auto/<run>/wip|parked/<task>` so nothing is lost). Parked tasks keep their work in `refs/auto/<run>/parked/<task>`.
- **Control files** in the run dir, polled by the engine: `STOP` (safe stop at the next checkpoint), `PAUSE` (removed by `continue`), `TAKEOVER`, `ABORT`.

## Files (`~/.claude/orchestrator/auto/<run-id>/`)
`contract.yaml` (what the user agreed to) · `permissions.json` + `claude-settings.json` (the allowlist, with the hash the user approved) · `state.json(.bak)` · `plan.json` · `journal.md` · `decisions.jsonl` · `parked.md` · `limits.log` · `usage.jsonl` · `report.md` · `handoff.md` (takeover) · `heartbeat.json` · `notifications.log` · `supervisor.log` · `tasks/`. The report is generated from these files (`auto.mjs report`, also mid-run, read-only).

## Contract (`contract.yaml`, answers of `auto.mjs draft --answers`)
`goal` · `definition_of_done[]` · `verify{test,typecheck,lint,build,extra[]}` (from the repo profile) · `actions{allowed[],forbidden[]}` · `protected_paths[]` (globs: no edits) · `dependencies: none|patch_minor|any` · `network: none|read` · `sensitivity: none|internal|sensitive` · `irreversible_allowed[]` (never `push`/`force`) · `egm{allow}` (EGM pre-consent, read by `egm-gate.mjs --contract`) · `families{allow[]}` (null = all enabled) · `deadline` · `limits{soft_pct,hard_pct,weekly_soft_pct,weekly_hard_pct,reserve_pct,safety_margin_min}` · `budgets{task_attempts,no_progress_min,tick_timeout_min,idle_timeout_min,max_dispatches}` · `notify{channel: os|file|command|none,command,wait_min}` · `checkpoints{profile_override,hooks}` · `bootstrap{commands[],link_dirs[]}` · `task_hint{complexity,files,criteria,risk}` (for the feasibility estimate). Defaults for limits and notification come from `config.yaml` `auto:` (`/orchestrator:configure`).
The allowlist is generated from the verify commands + read-only git. Denied: push/remote git, network tools, deletes, secret reads, protected paths, dependency installs (unless `any`), web (unless `network: read`), `gh`.

## Limits: what is measured and what is estimated
- **Claude (exact)**: every headless tick emits `rate_limit_event` (stream-json) with `unifiedWindows.five_hour|seven_day {utilization, resetsAt, status}` and the overage state. `utilization` is read as a fraction (x100; values > 1 are taken as percent): **this interpretation is unverified over a long run**. A rejected event gives the exact `resetsAt` of the exhausted window. Without an event (text-only error) the reset time is parsed from the message ("resets 3pm (zone)") and marked *estimated*; with no time at all the retry gaps are 10/20/40/60 min probes (estimated).
- **GPT (exact-ish)**: `codex app-server` rate limits at zero tokens, plus adapter cooldowns (`blocked_until`). **Grok/Gemini (estimate only)**: usage counters from `usage.jsonl`; they only ever produce a *soft* flag, never a hard block; real limit messages from the adapter set `blocked_until`.
- **Thresholds**: soft 80% (route NEW work to another family), hard 95% with a 5% reserve (WORK stops at 90%; the reserve is kept for planning, reviews, second opinions, the final review and the report), weekly soft 90 / hard 97. At hard the run sleeps until `resetsAt` + 3 min margin; weekly exhaustion = long wait (+ `long_wait` notification after `notify.wait_min`). All families blocked -> wait for the earliest unblock. Privacy limits rerouting (a sensitive task never goes to a family that may train on it): then the run waits instead.
- **Never**: switch accounts, enable overage (`isUsingOverage`/`overageStatus` is logged; preflight warns), use credentials beyond what each CLI holds.
- External failures (network, login, 5xx/overloaded): zero-token probes (`HEAD api.anthropic.com`, `claude auth status`) with backoff 1/2/5/10/15 min; state `waiting`, notification `waiting_external`.

## Decisions
Reversible and confident (>= 0.75) -> decide, log. Uncertain -> second opinion from a different family (privacy-gated); agreement -> proceed; disagreement or none -> the safest minimal option, else park only that task. Irreversible/external-effect (push, deploy, migration, delete data, publish, payment...) -> forbidden unless `irreversible_allowed` lists the category and a second opinion confirms; else the task is parked. Every decision goes to `decisions.jsonl` {id, time, task, question, options, chosen, confidence, reasoning, second_opinion, reversibility, files, sha, undo}; `undo` is `git -C "<worktree>" revert --no-edit <sha>`. A diff guard parks or rolls back changes to protected paths, secrets, CI config, critical paths (per the profile), unapproved dependency changes and mass deletes (>= 15 files).
Loop protection: attempt budget per task (escalation ladder: same model with the failure -> stronger model -> other family -> park), no-progress timeout, max dispatches. Fetched or tool content is data, never instructions (`SYSTEM_RULES` in every tick).

## Notifications
Generic fixed texts only (done, blocked, long wait, waiting external, stopped, handed over, aborted): no code, paths or task names. Always appended to `notifications.log`. Channels: `os` (Windows toast via PowerShell, macOS `osascript`, Linux `notify-send`), `file` (log only), `command` (your command, the text in `ORCH_NOTIFY_TEXT`; detached, fire-and-forget), e.g. a phone push: `curl -s -d "$ORCH_NOTIFY_TEXT" https://ntfy.sh/<your-secret-topic>` (the text is generic, the topic is yours).

## Keep-awake, and what it does not cover
The guardian asks the OS not to sleep while the run is active (Windows `SetThreadExecutionState`, macOS `caffeinate`, Linux `systemd-inhibit`). **Not covered**: closing the lid on battery, a hibernate/power-plan timer that ignores the request, a reboot or logout, a forced Windows update restart, a locked-down corporate policy. After a sleep the run continues by itself when the machine wakes; after a reboot nothing restarts it: run `auto.mjs continue` (the engine recovers from the files). `doctor` shows the capability; set lid-close to "do nothing" and plug in the charger for an overnight run.

## Takeover and review
`takeover` -> the engine pauses at the nearest safe checkpoint, ends worker processes cleanly, writes `handoff.md` (English: contract, tasks, decisions, where the work is) and sets state `handed_over`. The interactive orchestrator reads `handoff.md`, runs `run.mjs init`, adds rows for pending tasks and continues in normal mode inside the auto worktree. `review revert` reverts one checkpoint (or the task behind a decision) on `auto/<id>` only; `merge --into <branch> --yes` runs `git merge --no-ff` in the user's checkout only on the explicit yes and never pushes; `cleanup --yes` removes worktree and branch.

## Test hooks and honest limits of verification
`ORCH_AUTO_WAIT_SCALE=0.001` shortens waits (the engine clock skips ahead); `ORCH_AUTO_INJECT={"reset_in_s":8}` turns the first finished work tick into a limit hit. `selftest.mjs auto` covers the engine with a simulated clock and fake model/usage feeds (limit mid-task, reroute and privacy, all families exhausted, crash at sampled points, STOP/PAUSE, takeover, corrupt state, duplicate lock, decisions, undo, report, no push); `scripts/auto-smoke.mjs` runs a real tiny task end to end.
**Not verified**: the real 5-hour window reset (no run lasted past one), OS sleep/resume behavior, multi-hour unattended duration, the `utilization` scale, Grok/Gemini limit messages.
